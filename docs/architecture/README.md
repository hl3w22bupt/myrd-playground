## 二、目标与非功能约束（自需求推导）

功能范围：跳伞、物资拾取、武器射击、缩圈毒圈、AI 对抗五模块，单局 10 分钟内自然结束（AC1）。

| # | 非功能目标 | 来源 | 量化指标 |
|---|---|---|---|
| N1 | 纯浏览器端、免安装 | 需求定位 | 无客户端下载；首屏可交互 ≤ 5s（桌面宽带） |
| N2 | 落点复现 | AC2 | 同 seed 同输入序列 → 落地位置完全一致 |
| N3 | 数值可验收 | AC3/AC4/AC5 | 伤害/减伤/掉血速率与配置表一致，可自动化断言 |
| N4 | 帧率稳定 | 体验 | 桌面 60 FPS；中端移动设备 ≥ 30 FPS |
| N5 | 单局规模 | 需求 | 玩家 1 + AI ≥ 10（设计上限 19 AI + 玩家 = 20 实体） |
| N6 | 本期纯本地 | 范围 | 无后端依赖；网络同步不在本期承诺（见 §6 演进） |

**范围裁剪声明**：本期不做真实地形/角色骨骼动画资产、不做多人联网、不做账号系统。美术资源使用程序化几何 + 免费低模占位，保证玩法闭环优先（AC1–AC5 均不依赖资产品质）。

## 三、总体架构

核心原则：**仿真与表现分离**。玩法全部逻辑运行在无 DOM 依赖的确定性仿真核心中，Three.js 只做"快照 → 场景对象"的映射，UI 只读事件流。这直接服务于 N2（可复现）与 N3（数值可测）。

```
┌─────────────────────────────────────────────────────────────┐
│  UI 层（低频，React）      HUD/小地图（高频，原生 DOM/Canvas2D） │
│      ↑ 事件流 (GameEvent)          ↑ 直写 textContent         │
├─────────────────────────────────────────────────────────────┤
│  表现层 render/ (Three.js r185)                              │
│      场景构建 · 资源加载 · LOD · 相机 · 特效 · 对象池           │
│      ↑ 每 rAF 读 WorldSnapshot（只读）                        │
├─────────────────────────────────────────────────────────────┤
│  仿真核心 core/（纯 TypeScript，零 DOM 依赖，可 Node 运行）     │
│      fixed tick 50Hz · seeded RNG · ECS-lite 实体/系统        │
│      跳伞 · 移动 · 射击弹道 · 拾取 · 缩圈 · AI · 对局生命周期   │
│      ↑ 指令流 (PlayerIntent)                                 │
├─────────────────────────────────────────────────────────────┤
│  输入层 input/（键盘/鼠标 → PlayerIntent）                     │
│  内容层 content/（配置表 JSON：武器/物资/缩圈/地图）             │
└─────────────────────────────────────────────────────────────┘
```

关键推论：
- 仿真核心不 import Three.js，可在 Node + Vitest 中直接跑满局断言 AC2/AC3/AC4/AC5 —— 这是本次架构最重要的一条决策。
- 渲染层崩溃/加载失败不推进仿真状态（仿真不依赖渲染）；渲染层可整体降级（占位几何）。
- UI 只消费事件，不回写仿真状态，杜绝 UI 驱动逻辑。

## 四、决策记录（ADR）汇总

详细论证见各分文档，此处为结论与代价。

| ADR | 决策 | 为什么是它 | 主要代价 |
|---|---|---|---|
| ADR-001 | 渲染引擎选 **Three.js r185**，不选 Babylon.js / PlayCanvas / Unity WebGL | 玩法逻辑全部自研，引擎只需"渲染+数学"；生态与资料最多、体积小、TS 类型官方维护；团队上手成本最低 | 无内置 GUI/物理/Inspector，需自建少量基建（约 200~400 行） |
| ADR-002 | 物理与碰撞**自研**（高度场采样 + AABB + 射线检测），不引入 Rapier/Ammo | 本期碰撞需求仅三类，自研约 300 行、零 wasm 加载复杂度、完全确定性 | 不支持复杂凸体/刚体堆叠；二期若引入载具需替换（已预留接口） |
| ADR-003 | 仿真采用 **fixed timestep 50Hz + 渲染层可变 rAF + 插值** | AC2 要求落点可复现；可变 dt 无法保证 | 需处理 tick 追赶上限与插值（约 60 行） |
| ADR-004 | 实体组织用**轻量结构化实体 + 系统函数**（ECS-lite），不引入 bitecs 等 ECS 框架 | 实体上限 20，重型 ECS 无收益，纯增学习成本 | 字段访问非 SoA，性能余量小于真实 ECS（规模内足够） |
| ADR-005 | UI **React 19 + 原生高频层混合**：菜单/背包/结算用 React，HUD 数值与小地图直写 DOM/Canvas2D | React 重渲染不适合每帧更新；纯 DOM 又丢失 React 规范收益 | 两套 UI 代码风格并存，需约定分层规则 |
| ADR-006 | AI 用**有限状态机 + 分帧更新**，不做行为树/GOAP | 需求仅 5 类行为（巡图/拾取/索敌/开火/避毒），FSM 足够 | 行为复杂化后 FSM 会膨胀（二期可平滑替换决策器） |
| ADR-007 | TypeScript 锁 **5.9.x**，不上 TS 7（native preview） | npm 最新已是 7.0.2，但为 Go 原生移植新版，生态（类型/工具链）未稳定 | 后续升级需回归测试 |
| ADR-008 | 构建 **Vite + 零后端静态部署** | 纯前端；Vite 8 已发布但建议锁 Vite 7 稳定线 | — |

## 五、如何使用本设计

- **实现节点**：先读 [02-module-boundaries.md](./02-module-boundaries.md) 的目录结构与接口契约，按契约实现；数值一律走 `content/` 配置表，不允许硬编码。
- **测试节点**：验收映射见 [03-milestones-and-acceptance.md](./03-milestones-and-acceptance.md) §3，其中 AC2/AC3/AC4/AC5 均有 Node 侧自动化断言方案。
- **排期节点**：里程碑与依赖关系见 [03-milestones-and-acceptance.md](./03-milestones-and-acceptance.md) §1。
