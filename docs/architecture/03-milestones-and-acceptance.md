# 03 · 开发里程碑 与 验收映射

> 估算假设：1~2 名全栈实现者，全程使用本文档定义的架构。每个里程碑**必须**以"可运行 + 可验收"结束，禁止跨里程碑并行堆叠未验证功能。

## 1. 里程碑总览

```
M0 地基(0.5w) → M1 跳伞(1w) → M2 移动+地图(1w) → M3 物资(1w) →
M4 射击(1w) → M5 缩圈(0.5w) → M6 AI(1w) → M7 闭环+调优(1w)   合计 ≈ 7 周
```

| 里程碑 | 内容 | 交付物 | 验收（DoD） | 对应 AC |
|---|---|---|---|---|

## 2. 测试策略（三层，成本优先）

1. **Node 仿真断言（主体，vitest，覆盖 AC2/3/4/5 数值）**：`core` 零 DOM 依赖 → 测试直接 `createMatch({seed})` + 注入意图序列 + 跑 tick，断言世界状态。**不需要浏览器，跑得快，可进 CI。**
2. **渲染/性能冒烟（Playwright，仅 M0/M2/M7 各一次）**：加载页面、跑 30s、读取调试 HUD 的 FPS/draw calls 断言性能预算；不逐帧比对画面。
3. **人工体验走查（M7）**：手感、UI 可读性、跳伞/开伞节奏——只做体验判断，不做数值验收。

确定性是测试策略成立的前提：**任何破坏 `Math.random`/`Date.now` 禁令的 PR 直接打回**。

## 4. 风险与对策

| 风险 | 影响 | 对策 | 触发条件 |
|---|---|---|---|
| 跳伞手感调不平（AC2 落点偏差） | 中 | 参数化空气阻力模型（内容表暴露 `drag/glide`），加"落点预览圈"UI 辅助 | M1 连续 3 天不收敛 |
| AI 交火过强/过弱导致单局时长失控 | 高 | AI 状态机参数（反应延迟/命中率/搜索半径）进配置表；M7 用 10 局自动化采样调参 | M6 采样时长 >12min 或 <4min |
| 移动端帧率不达标 | 中 | 画质自动降档兜底；Low 档为硬底线（关阴影+降分辨率） | 中端机 Medium <30FPS |
| 自研碰撞出现穿墙/卡墙 | 中 | 移动用"先 X 后 Z"分离轴 + 速度钳制；缺陷用回放文件复现 | M2 冒烟出现 |
| 占位资产导致表现力不足、验收争议 | 低 | 需求 AC 均为数值/流程验收，不依赖美术；视觉打磨列为二期 | — |
| 跨设备浮点不一致（若二期联机） | 低 | 本期不承诺；二期联机选状态同步方案，不依赖 lockstep | 二期立项时 |

## 5. 二期演进预留（本期不做，只留边界）

- **多人联机**：`MatchHandle.tick(intents)` 已把"输入"与"状态"解耦，二期将本地输入替换为远端指令流（客户端预测 + 服务器权威）。`core` 无需重写 —— 这是本次架构为演进留出的**唯一**关键预留，且它免费（来自确定性设计）。
- **载具/复杂物理**：`movement` system 内部实现可替换为 Rapier，对外仍是 `PlayerIntent` → 状态变更，不影响其他 system。
- **内容扩量**：`content/` 配置表即内容管线，新增武器/物资/地图不改代码。
- **存档/战绩**：对局结果已有结构化 `MatchResult`，接后端只是传输层工作。
