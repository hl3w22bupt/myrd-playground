## 三、一手实测发现（按严重度）

### A（致命）可收集物零刷出——玩法主循环断裂
- 三局运行全程**场上没有任何可收集物**：超时判负时本局 0/20；HUD 计时正常走（60→0）。
- **量化留证**：移动端包 428 帧 + 结算包 400 帧，按 `game_state.gd` 五类收集物特征色（草绿/亮金/天蓝/品红/青碧）扫描，**零命中**（仅有的 34 个金色像素点经定位全部来自加载进度条与牛牛自身斑点边缘抗锯齿）。
- 对照：headless 门禁（smoke/playtest 机器人）机判收集/刷出全绿——**缺陷仅在真实浏览器 Web 运行期复现**，属门禁盲区（见 §六）。
- 桌面视口同样空场（剩余 36 秒时 0/20）→ **非移动端特有**。

### B（致命）角色移动全失效——键盘与触屏双双无效
- 移动端仿真：触屏虚拟摇杆右/下/左/上推 ×多组，`inputArrived=true` 但**牛牛零位移**，摇杆钮亦无任何视觉反馈。
- 桌面差分：键盘 W×6 / D×6 连按，牛牛零位移（排除了「触屏仿真伪影」的解释）。
- **像素级留证**：28 帧牛牛橙色斑点质心恒定于 (305-308, 305-307)，±2px 为待机呼吸动画；见 `.../steps/04-11 键盘W/D 系列` 与录屏帧。
- 对照：UI 控件（开始/重开/暂停按钮、Enter 确认）对触摸与键盘均正常响应——**UI 层输入通路正常，世界层（玩家移动+刷出）整体冻结**。方向不反向等基线无从核验（移动本身不存在）。

### C（严重）结算面板文字与按钮重叠
- 「时间到！本局得分 0/20 · 最高连击 ×0 · 历史最佳 0」一行压在「一键重开 (R)」按钮上，「按 确认 / 空格 一键重开」提示同时盖住两个按钮——两局超时结算均复现。
- 证据：`2026-10-14T06-11-20-v4-settlement-pause/steps/04-结算面板.png`。
- 违反 v4 需求「④3 结算页完整 / UI 无溢出遮挡」。

### D（中等）触屏专用 UI 泄漏到桌面环境
- 桌面视口下虚拟摇杆与「确认」标签仍然可见，且「确认」与底部提示条重叠——与 playtest kit §1.2「触摸 UI 只在带触摸屏的环境显示，桌面键盘环境完全不可见」的声明相悖。
- 证据：`desktop-diff/.../steps/04-开始后.png`（右下「确认」+ 左下摇杆）。

### 正常项（实测通过，供修复后回归对照）

## 五、处置结论

1. **打回工作流重做**：四维中①③④核心条目 FAIL，v4 验收整体不通过。打回范围 = 修复 A（Web 运行期刷出断裂）与 B（Web 运行期移动输入断裂）为主，连带 C（结算面板重叠）、D（触屏 UI 泄漏/重叠）；A/B 修复后 9 项 unverifiable 才具备观测条件，需整轮重验收。
2. **不通知用户真机试玩拍板**：「全部通过后上真机」条件不满足；游戏当前不可玩，试玩量表维持「待用户试玩」待修复后回流（本验收不代填、不伪造）。
3. **归因线索（供修复方，非验收结论）**：UI 层（Control 按钮/面板/计时 HUD）对真实浏览器事件全部正常，世界层（玩家 Input 轮询移动 + 生成器补齐）整体冻结而引擎内部计时/动画照常——建议优先排查 Web 构建下世界层节点与输入单量的运行期状态（如 tree pause/process mode/输入投递路径），headless 门禁与 Web 运行期的差异即病灶所在。
4. **门禁盲区警示（系统性发现）**：本轮 godot-smoke/preflight/fuzz/playtest/mobile-smoke 全绿与「线上不可玩」并存。既有门禁全部经**引擎级输入注入**（`Input.actionPress`）机判，覆盖不了「真实浏览器键盘/触摸事件 → 世界层响应」这一段；mobile-smoke 的「触摸管线通」只证明事件到达页面，不证明玩法响应。建议后续轮次在 mobile-smoke 中增加「真实事件驱动下牛牛位移 >阈值」「同屏可收集物 >0」两项观测断言（本验收的像素检测方法可直接复用为脚本逻辑）。
