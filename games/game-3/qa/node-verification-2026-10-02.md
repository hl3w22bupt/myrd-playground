## 一、本轮发现与修复（每条都是审读/断言抓出来的，不是文档润色）

### ① 关卡注释教的二段跳时机是致命错误（文档缺陷，玩家照做必死）

**缺陷**：`level.gd` 坑5 注释、`qa/playtest-kit.md` 提示行、
`qa/spec-numeric-verification-2026-09-27.md` §174 都写着
「第二跳在『回落越过起跳高度』后 ≈0.26s 再按为力学最优」。
数值复算（欧拉步进 1/60s + 对岸墙几何判据）与引擎实测（一次性探针，已删除）都证明：
按字面执行（第一跳后 ≈1.0s 才按第二跳）时玩家已回落到唇沿下方 ≈180px，
第二跳最大爬升只有 96.6px（v²/2g = 520²/2800），**无法再回到唇沿高度 → 必撞对岸墙死亡**，
跨距跌回单跳的 ≈176px，连 200px 的坑3 都过不了。

**实测曲线**（引擎逐帧，第一跳后延迟 → 跨距）：
最优在 **42–44 帧（≈0.70–0.73s）**，跨距 364px；0.37s（最高点）按只剩 ≈300px；
0.28s–0.72s 是坑5(280px) 的可玩窗口。

**修复**：`level.gd` 坑表 + 行内注释、`player.gd` 推导注释、`qa/playtest-kit.md`
提示行全部改为实测口径（第二跳在第一跳后 ≈0.70s 按最稳；窗口 0.28–0.72s；
两处危险时机显式写明后果）。`spec-numeric-verification` 是历史核验记录不改写，
以本记录为准。

### ② 坑宽余量承诺用了乐观解析值（承诺失真）

**缺陷**：坑表余量按「解析跨距 178/357px + 压边宽容 11px」记（坑2 余量 ≈39px、坑5 ≈88px），
但「+11px 宽容」与坑宽比较属重复计账；引擎实测（跨坑物理实证 rig）：
单跳跨距 **176px**、二段跳最优 **352px** → 真实余量是坑2 ≈26px、坑5 ≈72px。

**修复**：坑表改按实测值记，并注明实测来源（见 §三 的断言）。

### ③ 调参工作台「拖动 → R 重开一局即生效」实际是断的（功能缺陷）

**缺陷**：`player.apply_tuning()`（原名 `_apply_tuning`）只在 `Player._ready()` 调用一次；
`GameState.reset()` 在重开时重读了 `window.__GAME_TUNING__`，但**没有任何人把重读结果
应用回玩家** —— 调参工作台拖完滑杆按 R 重开，手感不变，只有整页刷新才生效。
`game_state.gd` reset() 注释与 `qa/tuning-params.md` 都承诺了「重开即生效」。

**修复**：入口公开化（`_apply_tuning` → `apply_tuning`），`main.gd` 的 `restart_run()`
在 `GameState.reset()` 之后调用 `player.apply_tuning(GameState.tuning)`。

### ④ FALL_LIMIT_Y 注释承诺「坠落全程可见」与常量矛盾（注释失真，数值不动）

`FALL_LIMIT_Y = 420` 是 spec.world 锁定值；相机下缘在 340（`main.gd` camera.limit_bottom），
判死发生在忍者坠出画面下缘之后 ≈7 帧（≈0.12s）。旧注释「坠落全程可见」与常量推导相反。
已改写为如实描述（这条线是物理兜底，不是表现层事件；死亡反馈由
忍者坠出画面 + 结算弹层 + 震屏承担）。**数值未动** —— 收进画面内属 spec 变更，须走策划案修订。

## 四、本轮被断言拦下的中间缺陷（断言不是摆设）

1. **rig 起跳点退化**：第一版把 rig 玩家放在「中心 = 左唇 − 半宽」且立即起跳 —— 该位置
   身体与平台的重叠为 0，玩家直接滑落（探针实测 min_y=202，从未离地）。修正为
   「先稳定 3 帧再起跳」，起跳瞬间玩家自动奔跑到的实际位置即最晚起跳位（与真实玩法一致）。
2. **`set_process_unhandled_input(false)` 入树前调用不生效**（Godot 4.3 实测）：rig 摘掉了
   全局输入路径，但该调用放在 `add_child` 之前时被忽略 —— 主时间线注入的 jump 动作
   照样送达 rig，第二跳被提前 ≈28 帧触发，二段跳档跨坑失败。**必须在 `add_child` 之后调用**
   （探针实证：入树前设置 → 注入动作后 jumps_used 变 2；入树后设置 → 保持 1）。
   修复与坑位说明已写进 `smoke.gd`。
