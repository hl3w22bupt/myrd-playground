# iOS Safari 真机实测清单（《疾风忍者跑》）

> 执行人：持 iPhone 的用户。全程约 15–20 分钟。每项结论记 `pass / partial / fail`，
> 证据按「命名规则」存入同目录 `artifacts/`，再按 `artifacts/README.md` 模板回写结果表。
> **这是唯一的有效验收口径**：`cdp-precheck/` 里的仿真预检不能替代本清单任何一项。

## 0. 环境登记（必填，缺一项则该轮结果不计）

| 项 | 记录 |
|---|---|
| 机型 | ________（如 iPhone 13 mini） |
| iOS / Safari 版本 | 设置 → 通用 → 关于本机（如 iOS 18.0 / Safari 18.0） |
| 网络 | Wi-Fi / 蜂窝（加载耗时强依赖它，必须记录） |
| 系统静音键 / 媒体音量 | 静音键状态 + 音量约几格（直接影响 C4 音效判定） |
| 省电模式 | 开 / 关（低电量模式会锁帧，C8 帧率判定必须记录） |
| 入口 URL | `https://leomac-studio.tail49399e.ts.net/apps/game-3/` |

录屏：控制中心开启屏幕录制（设置 → 控制中心 → 屏幕录制）。**整轮测试一条录屏搞定**，
命名 `rec-<机型>-<iOS>.mov`；截图命名 `c<编号>-<机型>-<说明>.png`。

## 1. 加载（C1–C3）

- [ ] **C1 冷加载**：Safari 无痕模式首次打开入口 URL。秒表记录「点开 → 出现进度条 →
  进度条走完 → 引擎画面出现（忍者可见）」总耗时与分段耗时。`partial` 阈值：>60s 即记 partial
  并注明网络。证据：录屏（进度条全程可见）。
- [ ] **C2 加载失败兜底文案**：（可选）飞行模式重开一次。进度条 100% 后若失败，应出现
  「加载失败：…」文案而非白屏/卡死。（只在资产通道异常时能触发，可跳过并标 skip。）
- [ ] **C3 横竖屏与安全区**：竖屏锁定与旋转各试一次；画面应始终铺满视口、无黑边漂移、
  HUD 四行文字不被刘海/底部横条遮挡。证据：`c3-<机型>-横竖屏.png` ×2。

## 2. 触控（C4–C7）—— 核心手感，全程录屏

- [ ] **C4 点按起跳**：在平地上点按右下「跳」键，忍者必须**当帧起跳**；连续点按地面节奏
  跳 5 次，无一次「按了没反应」。触控响应主观延迟 ≤ 1 帧可感延迟（约 0.1s）。
- [ ] **C5 二段跳**：空中再点一次，必须触发第二段跳；**连续三连点**时第三段必须无效
  （防三段跳，对应 `MAX_JUMPS=2`）。跨一个宽坑实测：单跳跨不过去、二段跳能跨过去。
- [ ] **C6 土狼时间**：从平台边缘**走出去**（不按跳）后约 0.1s 内补按跳，仍应地面起跳
  （`COYOTE_FRAMES=6`）；走出明显更久后按跳，应变成空中跳（只有一段）。
- [ ] **C7 跳跃缓冲**：在坑边**提前一点点**按跳（角色未落地），落地瞬间应自动起跳
  （`JUMP_BUFFER_FRAMES=6`），而不是吞输入。
- 证据：C4–C7 共用录屏，另附 `c5-<机型>-二段跳跨坑.png`（跨坑瞬间截图）。
- 若 C4–C7 手感不对：先别报 bug，用 `tuning-params.md` 的 URL 复现调优（如
  `coyote_frames`/`jump_buffer_frames` 拉到 10），确认是「数值问题」还是「链路问题」——
  数值问题回写参数即可，链路问题（点了完全没跳）才是真 bug。

## 3. 音效（C8–C9）—— iOS 特有风险区

- [ ] **C8 首次手势解锁**：进游戏后第一次点按「跳」，**同一次手势内**应听到起跳音效。
  iOS 的 AudioContext 初始 suspended，壳页已做手势内同步 resume（`game-page.ts` F1 补丁）；
  本项验证修复在真机生效。证据：录屏（画面 + 声音同录）。
- [ ] **C9 打断恢复**：播放中①锁屏 3 秒后解锁回前台，②切到后台再回来，③拨静音键再拨回。
  每次回来后下一次点按应有音效（壳页 visibilitychange + 下一次手势双兜底）。
  证据：录屏；异常时在 Safari 地址栏无法开控制台，直接描述现象即可。

## 4. 帧率与发热（C10–C11）

- [ ] **C10 帧率**：跑动 + 连续二段跳最繁忙的场景持续观察 30 秒：画面应流畅无肉眼可见
  掉帧/撕裂；省电模式关与开各测一次分别记录。iOS Safari 无帧率面板，以「肉眼流畅度」+ 录屏
  回放（慢放看是否跳格）为准。
- [ ] **C11 发热与降频**：连续游玩 5 分钟，记录机身发热主观等级（不烫手/温热/烫）与
  后半段是否出现掉帧。

## 5. 稳定性（C12）

- [ ] **C12 长跑与重开**：①连续玩 5 局（含失败重开、跑到底过关），第 5 局的跳跃/音效/
  计分必须与第 1 局一致（无状态残留）；②失败/胜利结算弹层出现后点「重开」按钮可复位。
  证据：录屏 + `c12-<机型>-第5局.png`。
