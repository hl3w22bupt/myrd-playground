# 《星尘收集者》试玩量表（Playtest Kit）

给真人试玩者与验收人用：5 维打分 + 调参回填闭环。桌面自动化门禁（`verify.sh` 三段 PASS）只证明「能跑、能玩、可重开」，
**不证明「好玩」**——好玩必须由本量表的人测结果给出。

## 一、试玩入口与环境

| 项 | 说明 |
|---|---|
| 游戏地址 | `<liveUrl>`（平台部署后的 Web 链接） |
| 调参工作台 | `<liveUrl>?tuning=1`（打开即右上角面板） |
| 桌面开关面板 | 按 **T** 键（工作台关闭时同理再按一次） |
| 浏览器 | 桌面 Chrome / Safari 最新两个大版本；真机另见 `ios-checklist.md` |
| 每轮时长 | 至少 3 局（1 局失败终局 + 1 局胜利终局 + 1 局中途放弃） |

> 工作台只做**运行时**数值覆盖，不会改写 `config/gameplay.cfg`；刷新页面即回到 cfg 默认值。

## 二、五维量表（每维 1-5 分）

| # | 维度 | 1 分 | 5 分 | 观察点（打分前先看这些） |
|---|---|---|---|---|
| 1 | **首 30 秒能否看懂玩法** | 需要别人讲解才会玩 | 打开页面 30 秒内自发收集并躲避 | HUD 一句话提示是否足够；是否有人误以为要「打陨石」；首次受击前是否理解护盾 3 格的含义；里程碑横幅/飘字是否被注意到 |
| 2 | **操控跟手感** | 飞船像在打滑/过冲 | 指哪打哪，停下立即停 | 松开按键后的滑行距离；贴边（边界 clamp）时是否卡顿；同时按两方向（斜向）速度是否明显更快；触屏摇杆另见 iOS 清单死区项 |
| 3 | **难度曲线是否平滑** | 前 30 秒就死，或 5 分钟无压力 | 失败局集中在 40-120 秒，且能说出「这局败在哪」 | 分数每跨 8 分（difficulty_step）陨石 +1 / 提速 15% 是否感知为「变难了」而非「突然被秒」；陨石出现时是否有 ≥0.5s 反应时间；是否有玩家完全停角落挂机刷分 |
| 4 | **收集与受击反馈是否爽** | 收了/被撞都「没感觉」 | 每次加分、每次扣盾都有明确反馈 | `+1` 飘字是否清晰可见；受击震屏 + 飞船闪烁是否被注意；里程碑横幅（每 10 分）是否带来正向情绪；胜利结算「新纪录」是否让人想截图 |
| 5 | **一轮结束是否想重开** | 结算后直接关页面 | 不用提示就点了「重新开始」 | 结算面板出现到点击重开的间隔；是否主动想「破纪录」；护盾耗尽与目标达成两种终局，重开意愿是否一样强 |

**判定基线**：5 维平均 ≥ 4.0 且任一维 ≥ 3 分人数 ≤ 1/3 → 通过；否则按第三节的映射表调参后重测。

## 三、调参映射（哪句抱怨 → 改哪个键）

面板在 `<liveUrl>?tuning=1`，拖滑杆即时生效（改数量类键会自动重铺战场）。

| 试玩者原话 | 优先改的键 | 方向 |
|---|---|---|
| 「看不懂要干嘛」 | 不调参，先改 HUD 文案 / 首屏引导 | — |
| 「太滑 / 太飘」 | `player_speed` ↓，或改 player.gd 加阻尼 | 80-600 |
| 「陨石太快躲不开」 | `difficulty_speed_per_level` ↓、`difficulty_speed_cap_scale` ↓ | 0-0.6 / 1.0-3.0 |
| 「太简单，闭眼玩」 | `max_asteroids` ↑、`difficulty_step` ↓、`difficulty_asteroids_per_level` ↑ | 0-20 / 0-30 |
| 「根本没机会反应」 | `asteroid_speed_min/max` ↓、`difficulty_asteroids_cap` ↓ | 0-300 / 10-400 |
| 「目标太远/太近」 | `score_target` ↑↓（0 = 无尽） | 0-60 |
| 「没有爽点」 | `score_per_crystal`、`milestone_step` ↓（横幅更频繁） | 1-10 / 0-30 |
| 「被撞一下就没了」 | `initial_shield` ↑、`damage_per_hit` ↓、`invincibility_seconds` ↑ | 1-10 / 0-5 / 0-3 |
| 「晶体太难找」 | `max_crystals` ↑、`respawn_delay_seconds` ↓ | 1-20 / 0-5 |

## 四、回填方式（改完数值 → 复制 → 回填）

1. 打开 `<liveUrl>?tuning=1`，把上一表对应的滑杆拖到候选值；
2. 点 **「复制调参链接」** —— 当前 17 个数值会被序列化成
   `?tuning=1&max_crystals=…&difficulty_step=…` 追加在当前页面地址后并写入剪贴板
   （浏览器拒绝剪贴板权限时，面板会直接把完整链接展示出来，手动复制即可）；
3. 把该链接原样贴进试玩记录的「调参链接」字段 —— 下次打开即是这套数值，无需再拖；
4. 每组候选数值对应一条试玩记录；定稿后由工程侧把数值写回 `config/gameplay.cfg`（人改，不在面板里做）。

### 试玩记录模板

```markdown
- 试玩人： / 日期： / 设备： （桌面/机型）
- 局数：3（失败局 / 胜利局 / 中途放弃局）
- 调参链接：<paste>
- 维度1 首30秒看懂： n/5  ← 观察到的证据
- 维度2 操控跟手感： n/5  ←
- 维度3 难度曲线：   n/5  ←
- 维度4 收集/受击反馈：n/5  ←
- 维度5 想重开：     n/5  ←
- 最想改的一件事：
```

## 五、与自动化门禁的关系

| 门禁 | 证明 | 不证明 |
|---|---|---|
| `verify.sh`（PREFLIGHT / GODOT_SMOKE / GODOT_FUZZ） | 输入→移动方向语义、收集、扣盾、终局、重开链路无回归 | 好玩、难度合适、反馈到位 |
| 本量表 | 好玩与调参方向 | 代码无回归 |

两者都要绿，缺一不可。
