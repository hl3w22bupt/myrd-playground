# 好玩判据验收模板（预置件③ · 策划线产出物模板）

> 用法：新线每批「好不好玩」验收时复制填写。红线：**机器不替人判断好玩——本模板是「人工验收的组织容器」，
> 判定人 = 主人（终裁）**；策划/团队只备料（可跑测试 + 观测口 + 构造面），不代行结论。
> 「四件套句式」= 每条好玩判据必须以四种机器可核件支撑：**可跑测试 / 机读观测口 / 构造面复现 / 数据通路**。

## 判据条目（逐条填写，每批 ≥3 条）

### 判据 F-<批次>-<序>：<一句话主观命题>

- **命题**：______（例：「消除瞬间的爽感足以支撑 5 局连续重开」——主观命题，终裁=主人）
- **四件套**：
  1. 可跑测试：`<repo>/<path>/ac-xx-<id>.spec.mjs`（check 指向**真实可跑**的测试文件——路径必须存在且 `node <file>` 退出码 0；禁止指向不存在/跳过的文件）
  2. 机读观测口：`__G2_XXX` 全局面或埋点事件（名称 + 采样方式）
  3. 构造面复现：固定 seed / 布局构造器（复现步骤一行）
  4. 数据通路：回收方式（内测 tag + 聚合器，判例 aggregate-nearmiss.mjs）
- **机器面结论**：______（只写「测试全绿 / 命中率 / 频控计数」等机判事实）
- **人工面结论（终裁栏，留白给主人）**：______

## 句式规范（防「机器替人拍板」措辞）

- 允许：「机制就绪（机器面全绿）」「感知待真人判定」「样本 N=…，校准值待回收」
- 禁止：「已验证好玩」「体验优秀」「DoD 已达标」及一切把主观结论写成已完成事实的措辞（判例 qa-v13-batch.mjs Q5 措辞机判词表）

## 与 spec 链的接口

- 每条判据的「可跑测试」在 spec acceptance 段的 `check` 字段字面引用（判例：`g2-blocks/scripts/contract-check.mjs --only <id>`）
- 人工面结论回写走**主人拍板记录**（黑板/任务书批复），机器不写「好玩」结论入任何 spec/报告
