## 1. M2 一句话与目标

> **把 M1 已验收的 1v1 核心循环原样带上微信小游戏 + 抖音小游戏：玩法零新增，平台适配 + 包体红线 + 真机门禁全绿。**

- 核心循环（追球/射门/进球/90s 计时）与数值单源 `constants.js` **不动**——确定性模拟核（60Hz + mulberry32）原样保留，bot-sim 契约照跑，双平台共用同一套 core。
- 目标平台从 `["web"]` 扩为 `["web", "wechat-minigame", "douyin-minigame"]`（spec meta.platforms，走 v1.3）。

## 2. 范围

**做**：平台入口壳层（wx/tt 生命周期）、触控输入映射、Canvas 适配与整数倍缩放、包体工程（主包 ≤4MB 红线，manifest `wechat_main_package_max_bytes=4194304` 已锁）、平台登录/分享、真机冒烟门禁、提审材料。
**不做（冻结项延续 + M2 追加）**：不做在线联机/排行榜对局（平台好友分仅本地展示候选，9/19 另议）、不做内购与广告变现（合规高危 + M1 负面清单延续）、不做多模式/联赛、不碰 Steam/Roblox、不立新游戏、《AI女友》不启动、资源 70/30 不变。

## 5. 预算与门禁红线（继承 + 新增）

1. 资产总量 ≤1,572,864B（1.5MB）不变；微信主包 ≤4,194,304B（4MB）为**硬红线**，抖音首包上限以当期文档复核后在 v1.3 锁值；
2. 超线处置顺序：压缩 → 图集合并 → 分包/远程资源 →（仍超）升级主人，**禁止砍核心循环**；
3. 确定性红线延续：core 内禁 `Math.random`/`Date.now`、浮点仅 IEEE 精确运算——跨平台逐字节一致是 M2.4 的锚，破坏即打回；
4. 红线 `input_to_shot_latency_ms` 在触屏链路上重新实测（触控事件→判定的全链路），实测值进 v1.3 定标，v1.2 的 ≤50 先行红线继续有效。

## 6. 风险与升级项

| 风险 | 等级 | 处置 |
|---|---|---|
| 平台包体/类目政策变动（上限、资质要求随政策调整） | 中 | M2.0 以当期官方文档复核，复核结论落文 v1.3；不凭记忆锁值 |
| 低端安卓机 Canvas 性能不达阈值 | 中 | 降级阶梯：特效裁剪 → 渲染整数倍缩放降档 → 帧率目标下调（阈值变更走 v1.4，禁止静默放宽） |
| 合规资质（软著/版号/主体资质）周期不可控 | 高 | **升级主人拍板**（见 §7-①）；材料办理与开发并行启动 |
| 平台 API 差异导致 adapter 膨胀 | 低 | adapter 单接口收敛；两平台差异清单落文，超 3 处分支即升级主策划裁决 |
| M1 DoD 9/19 复盘未通过 | — | M2 全线顺延，集中修 M1；不带病上平台 |

## 7. 需主人拍板项（M2.0 前给出，阻塞级）

1. **合规路径**：软著办理是否启动（周期常以月计，是 M2.5 提审的硬前置）；提审主体资质归属；
2. **双平台节奏**：微信先行提审、抖音跟进，还是双平台同期提审；
3. **变现边界确认**：M2 维持零内购零广告（当前默认），或授权引入平台激励广告（设计+合规双重影响，默认不做）。
