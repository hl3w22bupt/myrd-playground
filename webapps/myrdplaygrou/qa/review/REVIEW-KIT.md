## 一、使用指引（怎么用、看什么）

### 怎么用（核心闭环，单页完成，无弹窗跳转）

1. 打开 liveUrl → 首屏即「换算卡」：输入金额（默认 100），下方「从 / 到」两个下拉框选币种（8 种：CNY / USD / EUR / JPY / GBP / HKD / KRW / SGD）；
2. 换算结果**实时更新**，大字号显示在卡片中央，其下一行是所用汇率（如 `1 CNY = 0.1492 USD`）；
3. 两个下拉框中间的 **⇅ 交换按钮**：一键互换源/目标币种（验证双向换算最省事的入口）；
4. 页面下半部「常用币种一览」：以源币种为基准列出其余 7 种币的汇率明细（次级信息）；
5. 「汇率趋势」卡：默认近 7 天折线，点「近 30 天」页签切换；折线下方标注区间涨跌（颜色 + ▲/▼ 符号 + 百分比文字，三重编码）；
6. 你改过的金额与币种会**自动存入 localStorage**：刷新/重开页面后原样恢复（数据留存口径）；
7. 断网（或汇率 API 不可用）时：页面用本地缓存正常渲染，顶部出现「⚠ 当前展示缓存数据，汇率可能滞后」琥珀色提示，不白屏不报错。

### 看什么（对照拍板创作决策的核对面）

| 核对面 | 拍板口径 | 建议核对动作 |
|---|---|---|
| 视觉风格 | 清新明亮（#f0f9ff/#0ea5e9/#22c55e 方向 → 工程落地为浅薄荷基底 #f4fbf9 + 薄荷绿主色 #14b8a6，见 `.myrd/style-card.md`） | 首屏观感是否浅色清爽、主色统一、无暗沉色块 |
| 布局密度 | 宽松留白 | 卡片间距/内边距是否透气，不显拥挤 |
| 响应式优先级 | 双端自适应 | 手机（<768px 应单列）与电脑（>1200px 应换算卡+趋势卡双列）各开一次 |
| 交互密度 | 适度交互 | 核心闭环 3 步内完成：选币种 → 输金额 → 看结果/趋势；无多余点击 |
| 数据留存 | 本地保存（localStorage） | 改金额/币种 → 刷新 → 应恢复 |
| 界面语言 | 中文 | 全部文案应为自然中文 |

### ① 打开 10 秒内能否明白这个应用做什么、怎么用？（是/否 + 卡点）

- 作答格式：`① 是/否`；若否，卡点写具体（如「不知道先点哪里」）。
- 客观参照：首屏依次为「今日汇率」标题 + 更新时间 → 大号金额输入与换算结果 → 币种下拉 → 明细/趋势，均为中文标签；无登录墙、无引导弹窗（门禁 console/render 项全绿）。

### ② 核心流程能否无阻碍走通？（1-5 分 + 卡在哪一步）

- 流程：选币种 → 输金额 → 看结果 → 看趋势（7 天/30 天切换）。
- 作答格式：`② N 分`；若 <5，写卡在哪一步（如「下拉框不好点」）。
- 客观参照：DOM 向取证 15/15 PASS —— CNY→USD 结果与公开汇率快照复算误差 0.008%（≤0.01%）、USD→CNY 双向一致、交换按钮生效、7 天 6 点/30 天 23 点折线均重绘且涨跌标注可见；触控目标 ≥44px。

### ③ 观感与风格统一（1-5 分：排版层级 / 留白 / 对比度 / 与拍板视觉风格的一致性）

- 作答格式：`③ N 分`（可附一句话，如「结果字号够醒目，但卡片间距偏紧」）。
- 客观参照（对照工程内 `.myrd/style-card.md`）：浅色基底 #f4fbf9 + 薄荷绿 #14b8a6 + 天蓝 #38bdf8 辅助；换算结果 44px ≈ 正文 15px 的 2.9 倍（首要视觉焦点）；涨跌「红涨绿跌 + ▲/▼ + 百分比」三重编码，非仅靠颜色；正文对比度 ≥4.5:1。**任何你在观感上的不适都请在分值中体现**，这是四问里唯一纯主观的一问。

### ④ 移动端可用性与阻断性缺陷（有/无 + 缺陷描述与复现路径）

- 作答格式：`④ 有/无`；若有，写「现象 + 复现路径」（如「iPhone Safari 打开后横屏，趋势图溢出屏幕：打开→切 30 天→横屏」）。
- 客观参照：preHook `webapp-smoke` 门禁本轮（2026-10-16 13:48）机判全绿 PASS —— 390×844 移动仿真下：网络全通 / console 零错误 / 首屏有内容 / 触摸事件到达 DOM / 视口无横向溢出（scrollWidth=390=clientWidth）；DOM 向取证移动端单列、桌面 1440px 双列均无溢出。**机判全绿 ≠ 体验过关**——真机手感（点按准不准、滚得顺不顺）只有你能下结论。
